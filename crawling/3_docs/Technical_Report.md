# Technical Report — 화장품 리뷰 구매 가이드 서비스

## 1. 개요

본 프로젝트는 무신사·올리브영·쿠팡 3개 쇼핑몰에서 화장품 리뷰 데이터를 크롤링하고, 순환신경망(LSTM/GRU)과 Transformer 기반 감성분석 모델을 학습시켜, 소비자가 상품을 검색하면 리뷰를 분석해 **구매 추천 여부·장단점·대표 리뷰**를 즉시 보여주는 Streamlit 웹 서비스를 구현한다.

**머신러닝/딥러닝으로 해결한 부분**: 사람이 수백 건의 리뷰를 직접 읽지 않아도, 신경망 모델이 텍스트만으로 긍정/부정을 자동 분류하여 소비자의 구매 결정을 돕는다.

## 2. 데이터 수집

| 플랫폼 | 수집 건수 | 수집 방식 |
|---|---|---|
| 무신사 | 231,029건 | Selenium 기반 직접 크롤링 |
| 올리브영 | 222,451건 | 팀원(임현우) 크롤링 |
| 쿠팡 | 78,484건 | 팀원(김동호) 크롤링 |
| **합계** | **531,964건** | 3명 데이터 통합 |

### 2.1 크롤링 과정에서 겪은 문제와 해결

**문제 ① 선택자 오류로 상품 정보 미수집**
무신사는 React 기반 SPA(Single Page Application)로, 초기에 예상했던 HTML 선택자(`li.li_box` 등)로는 상품이 0건 검색되었다. 브라우저 개발자도구로 실제 렌더링된 DOM을 직접 분석해, `a[data-item-id]` 속성에 상품 정보(브랜드·가격·이름)가 데이터 속성으로 직접 노출되어 있음을 발견하여 선택자를 수정했다.

**문제 ② 리뷰 일부만 수집됨 (무한 페이지네이션)**
"이전 후기 보기" 버튼을 클릭하는 방식으로 추가 리뷰를 가져오려 했으나, 같은 페이지가 무한히 반복 크롤링되는 문제가 발생했다. 원인은 해당 버튼이 실제로는 페이지 이동이 아니라, 별도의 리뷰 전용 페이지(`review/goods/{product_id}`)가 **스크롤 시 추가 리뷰를 동적으로 로드하는 무한스크롤 구조**였기 때문이다. 페이지 이동 로직을 `window.scrollTo()` 자동 스크롤 시뮬레이션으로 전환하여 상품당 평균 30~150건의 리뷰를 안정적으로 수집했다.

## 3. 데이터 전처리 및 라벨링

### 3.1 라벨링 문제: 평점 기반 분류의 클래스 불균형

감성분석 모델 학습에는 긍정/부정 정답(label)이 필요하다. 평점을 기준으로 1~2점을 부정, 4~5점을 긍정으로 분류했을 때, 무신사 데이터는 **부정 비율이 0.4%(973건)** 에 불과했다. 이는 구매 만족도가 높은 사용자만 평점을 남기는 무신사 플랫폼의 구조적 특성 때문이며, 이 상태로 학습하면 모델이 모든 입력을 "긍정"으로만 예측해도 97% 이상의 정확도가 나오는 무의미한 모델이 된다.

### 3.2 1차 시도: 키워드 기반 라벨링과 그 한계

평점 대신 리뷰 텍스트 내 부정 키워드(자극, 트러블, 별로, 환불 등)를 기준으로 직접 라벨을 재구성했다. 부정 비율을 21.9%까지 끌어올렸으나, **단순 키워드 매칭 방식은 오탐(false positive)이 많았다**. 예를 들어 "자극이 전혀 없어요"처럼 명백히 긍정적인 문장도 "자극"이라는 단어가 포함되어 있다는 이유만으로 부정으로 잘못 분류되는 사례가 다수 발견되었다 (검증 결과 2,088건의 오탐 확인).

### 3.3 최종 해결: 멀티플랫폼 통합 + 실제 평점 기반 라벨링

팀원이 크롤링한 올리브영(부정 35,359건, 15~17%)과 쿠팡(부정 5,667건, 7.6%) 데이터는 **실제 평점 기준으로도 충분한 부정 비율**을 보였다. 이에 3개 플랫폼 데이터를 통합하고, 키워드 추측이 아닌 **실제 평점(1~2점=부정, 4~5점=긍정, 3점 제외)** 으로 일관되게 재라벨링했다.

다만 무신사 데이터 비중이 커서(전체 531,964건 중 무신사가 다수) 그대로 합치면 부정 비율이 다시 8.4%로 낮아지는 문제가 발생했다. 이를 해결하기 위해 **긍정 클래스를 언더샘플링**(458,616건 → 125,997건 무작위 추출)하여 최종적으로 **부정 25.0% : 긍정 75.0%** 비율의 학습 데이터셋(167,996건)을 구성했다.

| 단계 | 부정 비율 | 데이터 출처 |
|---|---|---|
| 무신사 평점 기준 | 0.4% | 무신사 단독 |
| 키워드 추측 (1차 시도) | 21.9% | 무신사 단독, 오탐 다수 |
| **3사 통합 + 평점 기반 + 언더샘플링 (최종)** | **25.0%** | 무신사+올리브영+쿠팡 |

### 3.4 텍스트 전처리

1. **결측치 제거**: 리뷰 텍스트 또는 라벨이 없는 행 제거
2. **정제**: 정규식(`[^ 가-힣]+`)으로 한글과 공백만 남기고 특수문자·이모지·숫자 제거
3. **중복 제거**: 동일한 정제 텍스트를 가진 리뷰 제거 (1,414건 제거)
4. **형태소 분석**: KoNLPy의 Okt 형태소 분석기로 토큰화. 한국어는 띄어쓰기만으로 단어를 구분할 수 없어 필수적인 과정이며, 166,471건 처리에 약 5분 소요됨

전처리 후 최종 학습 가능 데이터: **166,471건**

## 4. 모델 설계 및 학습

### 4.1 공통 전처리 파이프라인

- Tokenizer: 빈도 상위 40,000단어로 정수 인코딩 (Keras `Tokenizer`)
- Padding: 최대 길이 100단어로 패딩 (`pad_sequences`)
- 데이터 분리: 학습 90% / 테스트 10% (`stratify`로 클래스 비율 유지)
- 출력: `to_categorical`로 원-핫 인코딩 (2-class)

### 4.2 비교한 3가지 신경망 구조

세 모델 모두 동일한 데이터·전처리·하이퍼파라미터(Embedding dim=32, batch_size=128, optimizer=RMSprop, EarlyStopping patience=3)로 학습하여 공정하게 비교했다.

**① LSTM (기준 모델)**
```
Embedding(40,001, 32) → LSTM(64) → Dense(16, tanh) → Dense(2, softmax)
```

**② GRU**
```
Embedding(40,001, 32) → GRU(64) → Dense(16, tanh) → Dense(2, softmax)
```

**③ Transformer (간이 인코더)**
```
Embedding + Positional Embedding → MultiHeadAttention(heads=2) → LayerNorm
→ FeedForward(64) → LayerNorm → GlobalAveragePooling1D → Dense(16, tanh) → Dense(2, softmax)
```

순환신경망(LSTM/GRU)을 우선 채택한 이유는, 리뷰가 문장 형태로 단어의 순서와 맥락이 중요하기 때문이다. 단순 키워드 매칭(3.2절)이 실패한 것과 달리, 순환신경망은 "자극이 전혀 없어요"의 "전혀 없어요"라는 부정어까지 함께 학습하여 맥락을 반영한 판단이 가능하다.

### 4.3 학습 결과 비교

| 모델 | 정확도 | Loss | 부정 정밀도 | 부정 재현율 | 부정 F1 | 파라미터 수 | 학습시간 | 에포크 |
|---|---|---|---|---|---|---|---|---|
| LSTM | 94.2% | 0.169 | 89.7% | 86.6% | 88.2% | 1,305,938 | 269초 | 9 |
| **GRU** | **94.3%** | **0.166** | 89.2% | 87.8% | **88.5%** | 1,299,922 | **207초** | **7** |
| Transformer | 93.8% | 0.175 | 88.9% | 85.8% | 87.3% | 1,293,330 | **118초** | 7 |

**분석**: GRU는 LSTM보다 구조가 단순함에도(게이트 수 적음) 정확도·F1 모두 최고치를 기록했고, 가장 적은 에포크(7회)로 수렴했다. Transformer는 어텐션 연산의 병렬화 덕분에 학습 속도가 가장 빨랐으나(118초), 정확도는 셋 중 가장 낮았다. 이는 본 데이터의 리뷰 문장이 최대 100단어 내외로 짧아, 장거리 문맥 포착에 강점이 있는 Transformer의 장점이 충분히 발휘되지 못한 것으로 해석된다. **결론적으로 본 프로젝트 규모(약 16만 건, 짧은 리뷰 문장)에는 GRU가 정확도와 학습 효율성 면에서 가장 적합했다.**

## 5. 서비스 구현 (배포)

Python 기반 웹 프레임워크 **Streamlit**으로 서비스를 구현했으며, 4가지 기능을 제공한다.

1. **전체 통계**: 학습 데이터 전체의 감성 분포·평점 분포·리뷰 키워드 Top 20 시각화
2. **상품 구매 가이드**: 상품 검색 시 ① 구매 추천도 배지(✅추천/🙂괜찮음/⚠️신중/❌비추천, 긍정비율 기준 4단계) ② 장점·단점 키워드(긍정/부정 리뷰에서 각각 추출, 브랜드명·불용어 제거) ③ 대표 긍정/부정 리뷰 인용문을 제공하여 소비자가 다수 리뷰를 직접 읽지 않고도 구매 여부를 빠르게 판단할 수 있도록 지원
3. **실시간 감성 예측**: 임의의 문장을 입력하면 즉시 긍정/부정 판단. 실제 데이터에서 추출한 대표 예시 버튼(긍정·부정 각 7개, 클릭마다 랜덤 노출) 제공
4. **모델 선택**: LSTM/GRU/Transformer 중 선택하여 예측에 사용할 모델을 전환, 선택한 모델의 정확도·F1·학습시간·파라미터 수를 실시간으로 비교 표시

### 5.1 코드 구조

```
app.py              실행 진입점, 캐싱(@st.cache_data/@st.cache_resource), 페이지 라우팅
dashboard_ui.py      Streamlit 화면 렌더링 함수 (st.* 호출 전담)
sentiment_utils.py   데이터 로딩, 모델 추론, 키워드/구매추천도 계산 (Streamlit 비의존 순수 로직)
```
역할을 분리하여 UI와 비즈니스 로직을 독립적으로 테스트·재사용할 수 있도록 설계했다.

## 6. 한계 및 향후 개선 방향

- **데이터 노이즈**: 일부 리뷰는 평점과 텍스트 내용이 불일치한다 (예: "워낙 유명한데 주문했는데 좋네요"가 평점 1점). 실제 사용자가 평점을 잘못 누르는 등의 노이즈이며, 이는 100% 정확도를 달성할 수 없는 근본적 한계다. 94% 수준의 정확도는 이러한 실제 노이즈를 감안할 때 의미 있는 결과로 판단된다.
- **장단점 키워드의 표현력**: 현재는 단순 빈도 기반 키워드 나열(예: "촉촉하고", "순하고")로 제공되며, "보습력이 좋다는 평이 많습니다"와 같은 자연어 문장 요약으로 발전시킬 수 있는 여지가 있다.
- **커버리지 한계**: 검색 가능한 상품은 크롤링된 2,130개 상품으로 제한되며, 신상품이나 미수집 상품은 검색되지 않는다.
